# 그라운드 4회차 링 버퍼 버전 발표 대본

대상: 「그라운드_4회차_LSTM_링버퍼_추가_방경식.pptx」의 11장 순서

예상 발표 시간: 약 7~8분. 슬라이드를 가리키거나 잠시 쉬는 시간에 따라 달라집니다.

1. **표지**

   안녕하세요. 방경식입니다. 이번 4회차에서는 낙뢰방호장치의 센서 데이터를 분석하기 위한 LSTM 모델을 학습하고 성능을 평가했습니다. 임베디드에서 최근 데이터를 일정한 크기로 보관할 수 있도록 링 버퍼도 구현했습니다.

   3회차에서 검토한 전처리와 시계열 입력 구성을 바탕으로, 이번에는 실제 프로그램을 실행하고 결과를 확인했습니다. 센서 기준과 데이터 구성, 링 버퍼, 모델 평가, 앞으로의 개발 계획 순서로 말씀드리겠습니다.

2. **표준 센서 범위와 기준값**

   먼저 교육계획서 마지막 표에서 센서의 측정 범위와 기준값, 측정 주기를 확인했습니다. 대지전위와 번개센서는 100밀리초, 누설전류와 입력전압은 1초 주기입니다. 제한소자 온도는 60초, 습도와 외기온도는 60분 주기입니다.

   누설전류 기준 1밀리암페어는 입력 단위에 맞춰 0.001암페어로 기록했습니다. 온도 기준 25도는 절대온도인지 온도 상승량인지 확인이 필요해 자동 위험 판정에 적용하지 않았습니다.

   이 표는 센서 사양을 설명합니다. 실제 시간별 측정값이나 정상·위험의 정답은 포함하지 않으므로, 이번 학습에는 별도로 만든 합성 데이터를 사용했습니다. 표준 설정에 맞춘 실측 재학습은 앞으로 진행할 작업입니다.

3. **학습 데이터 구성**

   전처리한 입력은 총 882개입니다. 이 중 441개는 학습에, 147개는 설정을 검증하는 데, 나머지 294개는 최종 성능 평가에 사용했습니다.

   하나의 입력은 100밀리초 간격으로 묶은 16개 시점입니다. 시점마다 센서값 10개와 결측 표시 10개를 사용해 총 20개 특징을 구성했습니다. 약 1.6초 분량을 함께 보고 정상과 위험을 구분하는 방식입니다.

   같은 이벤트의 데이터가 학습과 평가에 섞이지 않도록 먼저 분리했고, 정규화 기준도 학습 데이터에서만 계산했습니다. 여기서 882개는 입력 묶음의 개수입니다. 일부 구간이 겹치기 때문에 독립적인 낙뢰 사례 882건을 의미하지는 않습니다.

4. **링 버퍼의 역할**

   센서 데이터가 계속 들어오면 모델이 사용할 최근 구간을 유지해야 합니다. 이를 위해 고정된 크기의 공간을 반복해서 사용하는 링 버퍼를 구현했습니다.

   표를 보시면, 1번부터 66번까지 보관한 상태에서 67번 데이터가 들어오면 가장 오래된 1번 자리를 사용합니다. 그러면 보관 구간은 2번부터 67번으로 바뀌고, 모델 입력으로 준비하는 최신 16개도 52번부터 67번으로 이동합니다.

   이번 데모의 용량 66개는 입력 16개와 과거 5초분인 50개를 합한 값입니다. 전처리한 특징과 시간, 유효성 정보를 함께 저장합니다. 저장 배열의 크기가 계속 늘어나지 않기 때문에 메모리가 제한적인 임베디드 장치를 고려한 구조입니다. 실제 장치의 용량은 필요한 기록 구간과 메모리 예산에 맞춰 다시 결정하겠습니다.

5. **링 버퍼 실행·검증 결과**

   링 버퍼 데모에서는 합성 데이터 3,600개를 순서대로 입력했습니다. 입력이 계속 들어와도 버퍼에는 최대 66개만 남았고, 오래된 데이터를 3,204회 덮어썼습니다.

   입력을 구성하는 기능은 총 882개의 시퀀스를 준비했습니다. 입력 크기인 1 곱하기 16 곱하기 20은, 한 번에 시퀀스 하나를 전달하고 그 안에 16개 시점과 20개 특징이 있다는 뜻입니다.

   버퍼 배열의 데이터 크기는 5,874바이트입니다. 이 값에는 모델이나 전처리, 프로그램 전체의 메모리는 포함하지 않았습니다. 또한 데이터가 부족하거나 최신 구간에 무효 입력이나 시간 간격 오류가 있으면 입력 준비를 보류하도록 구현했습니다.

   이번 결과는 PC에서 합성 CSV를 재생한 결과입니다. 현재는 최근 데이터를 보관하고 모델에 전달할 입력을 만드는 단계까지 구현했으며, 학습한 모델과의 실시간 연결은 후속 작업입니다.

6. **LSTM 구조와 학습 실행**

   다음은 LSTM 모델과 실제 학습 화면입니다. LSTM은 여러 시점의 데이터를 순서대로 처리하는 모델입니다. 이번에는 은닉 유닛 16개를 가진 한 계층의 작은 모델을 구성했습니다.

   초기 학습률은 0.001이고, 한 번에 32개의 입력을 묶어 학습했습니다. 학습 데이터 전체를 한 번 학습하는 과정을 한 회차로 세어 최대 50회까지 진행하도록 설정했습니다. 검증 손실이 정체되면 학습률을 줄이고, 개선이 계속 없으면 조기 종료하는 조건도 넣었습니다.

   이번 실행에서는 50회까지 학습했습니다. 화면의 검증 F1이 1.0까지 올라갔지만, 최종 성능은 별도로 남겨둔 평가 데이터에서 확인했습니다.

7. **학습 곡선과 PR 곡선**

   왼쪽 그래프에서 학습 손실은 약 0.676에서 0.021로, 검증 손실은 약 0.629에서 0.019로 감소했습니다. 두 곡선을 통해 합성 데이터에 대한 학습이 진행된 것을 확인했습니다. 다만 50회까지 개선이 이어졌으므로, 50회가 최적 학습 횟수라고 확정하지는 않았습니다.

   오른쪽 PR 곡선은 판정 임계값을 바꿨을 때 위험을 얼마나 찾아내는지, 위험이라고 판단한 결과가 얼마나 정확한지를 함께 보여줍니다. 이번에는 곡선 면적이 높았지만, 실제로 사용하는 임계값에서 오경보가 생기는지도 따로 확인해야 합니다.

   판정 임계값은 검증 데이터에서 선택하고, 최종 평가에서는 그 값을 고정했습니다. 다음 슬라이드에서 그때의 실제 분류 결과를 설명하겠습니다.

8. **LSTM의 미탐지와 오경보**

   최종 평가 데이터는 정상 204개와 위험 90개, 총 294개의 시퀀스입니다. LSTM은 위험 90개를 모두 위험으로 판단해 이번 평가에서 미탐지는 0개였습니다. 반면 정상 데이터 중 46개를 위험으로 판단해 오경보가 발생했습니다.

   위험을 찾아낸 비율인 재현율은 100퍼센트입니다. 위험이라고 판단한 결과 중 실제 위험의 비율인 정밀도는 약 66.18퍼센트이고, 두 지표를 함께 반영한 F1은 약 79.65퍼센트입니다.

   정상 데이터에서 오경보가 발생한 비율은 약 22.55퍼센트입니다. 따라서 이번 결과에서는 위험을 놓치지 않았다는 점과 함께 오경보를 줄여야 한다는 과제를 확인했습니다. 이 수치는 합성 데이터의 시퀀스 기준 결과이며, 실제 낙뢰 감지 성능은 실측 데이터로 다시 평가해야 합니다.

9. **Logistic Regression과 비교**

   비교를 위해 더 단순한 로지스틱 회귀 모델도 같은 데이터로 평가했습니다. 이 모델은 이번 합성 평가 데이터에서 미탐지와 오경보가 모두 0개였고, F1은 1.0이었습니다.

   두 모델의 검증 점수가 같을 때는 구조가 단순한 모델을 우선하도록 설계했으며, 이번에는 로지스틱 회귀를 우선 추천했습니다. 모델 추천은 검증 데이터에 근거했습니다.

   이번 실험에서는 LSTM의 추가 복잡성이 주는 이점을 확인하지 못했습니다. 앞으로 실제 시간 변화가 포함된 데이터를 확보해 두 모델을 동일한 조건에서 다시 비교하고, 성능과 장치 자원 사용량을 함께 보고 선택하겠습니다.

10. **구현 성과와 검증 범위**

   이번에 구현한 범위는 데이터 전처리와 입력 구성, 모델 학습과 평가, 모델 저장, 그리고 링 버퍼와 시퀀스 생성입니다. 기존 검증에서 전체 자동 테스트 125개가 통과했고, 저장한 모델을 다시 불러온 평가 결과도 일치했습니다.

   현재 데이터는 프로그램의 동작을 확인하는 데 의미가 있습니다. 다만 합성 데이터이며, 최종 평가에 포함한 위험 이벤트 그룹도 두 개입니다. 겹치는 구간에서 만든 위험 시퀀스 90개를 독립적인 실제 낙뢰 사례 90건으로 볼 수는 없습니다.

   따라서 현재 성과는 학습·평가 프로그램과 최근 입력을 유지하는 기능을 구현하고 검증했다는 것입니다. 실제 장치 성능과 낙뢰 발생 전 예측 가능성은 별도로 검증할 과제입니다.

11. **실측 검증과 임베디드 적용**

   앞으로는 실제 측정 데이터를 확보하고, 센서 기준값의 의미와 정상·위험의 정답 기준을 확인한 뒤 개발을 이어가겠습니다. 후속 작업은 크게 미구현 기능 연결, 모델 보완, 테스트 확대입니다.

   먼저 링 버퍼에서 준비한 입력을 모델 추론에 연결하고, 추론 결과에 따른 상태 판단과 자동 이벤트 기록을 구현하겠습니다. 입력을 신뢰하기 어려운 경우에는 판정을 보류하는 상태도 구분하겠습니다. 이후 모델 변환과 경량화를 진행해 목표 MCU에 적용하겠습니다.

   모델 보완에서는 실제 데이터로 두 모델을 다시 학습하고, 입력 길이와 특징, 모델 크기, 판정 임계값을 검증 데이터에서 비교하겠습니다. 위험을 놓치는 경우를 억제하면서 오경보도 줄일 수 있는지 확인하겠습니다.

   테스트는 센서가 동시에 이상을 보이는 상황, 통신 지연과 재연결, 오랫동안 연속으로 데이터를 받는 상황까지 확대하겠습니다. 입력부터 판단과 기록까지 연결한 전체 흐름도 확인하고, 실제 MCU에서 메모리 사용량과 실행시간을 측정하겠습니다.

   이번 4회차에서는 PC에서 학습·평가를 실행하고, 임베디드 적용에 필요한 링 버퍼와 입력 생성 기능을 구현했습니다. 다음 단계에서는 이를 실측 데이터와 실시간 동작으로 연결하겠습니다. 이상으로 발표를 마치겠습니다.
