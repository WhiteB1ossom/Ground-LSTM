# 실시간 통합 개발 발표 대본

실험: integrated-20261012. PPT 11장과 같은 순서. 약 7~9분이며 숫자를 읽는 속도에 따라 조절합니다.

## 1. 실시간 통합 개발

안녕하세요. 방경식입니다. 이번에는 학습과 링 버퍼의 개별 실행을 연결해, 센서 입력부터 추론, 알림 판단, 이벤트 저장까지 이어지는 PC 프로그램을 구현했습니다. 데이터 수를 늘리고 서로 다른 조건을 시험했으며, 모델 변환과 C++ 전처리 검증도 진행했습니다. 오늘 보여 드리는 성능은 합성 데이터에서의 소프트웨어 검증 결과입니다. 실제 낙뢰 성능이나 보드 탑재를 완료했다는 뜻은 아닙니다.

## 2. 센서 범위와 판정 기준

이 표는 제공 자료의 센서 범위와 기준값입니다. 범위는 입력 품질을 확인하는 범위이고, 위험 판정 기준과는 따로 관리합니다. 누설전류 1밀리암페어는 입력 단위에 맞춰 0.001암페어로 기록했습니다. 대지전위 2와 습도 60퍼센트도 보존했습니다. 다만 초과할 때 위험인지, 미달할 때 위험인지, 같은 값도 포함하는지는 자료만으로 확정하지 않았습니다. 온도 25도도 절대온도인지, 외기온도나 다른 기준 대비 상승량인지 확인이 필요합니다. 코드에서는 초과, 미달, 동일값, 구간 안팎과 같은 비교를 명시하도록 바꿨습니다. 현재 물리 위험 규칙은 비활성 상태입니다. 이 표는 시간별 측정값과 정답이 있는 데이터셋이 아니라 센서 사양입니다.

## 3. 확대 데이터 구성

학습과 평가에는 60개 합성 시나리오의 36,000행을 사용했습니다. 정상 잡음, 기준 주변 값, 단일 센서 변화, 복합 변화, 위험 전환과 회복을 나눠 만들었습니다. 장애 검증용 6,000행은 학습에 넣지 않았습니다. 별도로 72,000행, 즉 2시간의 정상 연속 입력도 만들었습니다. 전처리 후 학습 4,860개, 검증 1,620개, 테스트 1,620개로 총 8,100개 입력 창이 생성됐습니다. 같은 획득 세션은 분할에 섞이지 않게 했고, 정규화는 학습 데이터에서만 계산했습니다. 겹치는 창이 있으므로 8,100개를 독립적인 낙뢰 사건 수로 해석하면 안 됩니다.

## 4. 링 버퍼와 이벤트 기록

링 버퍼는 최근 전처리 특징을 고정된 공간에 보관합니다. 이번 선택 모델은 64개 시점을 입력으로 사용하고, 과거 5초분 보관 여유 50개를 더해 버퍼 용량을 114개로 설정했습니다. 표의 번호는 동작 설명용입니다. 115번이 들어오면 가장 오래된 1번 자리를 사용해 2번부터 115번을 유지합니다. 최신 모델 입력도 51번부터 114번에서 52번부터 115번으로 이동합니다. 시간 간격이나 유효성이 맞지 않으면 모델에 이전 입력을 다시 전달하지 않습니다. 원본 관측은 별도 제한된 과거 기록에 보관하고, 경보가 나면 과거 5초와 이후 2초를 이벤트로 저장합니다.

## 5. 실제 재생 타임라인

이 화면은 테스트 입력 중 실제 재생한 한 합성 세션입니다. 위에는 대지전위와 자료의 2볼트 기준선을, 아래에는 모델 점수와 AI 임계값을 같은 시간축에 표시했습니다. 2볼트 선은 위치를 비교하기 위한 자료 기준선이며 자동 위험 판정에 사용하지 않았습니다. 아래 띠는 합성 정답의 위험 구간, 프로그램 경보, 판정 불가 구간입니다. 시작할 때는 64개 시점이 모이지 않아 판정 불가로 표시됩니다. 이후 최근 입력으로 점수를 계산하고, 2회 연속 임계값 이상일 때 경보를 시작합니다. 재생 배속을 바꿔도 관측 시각과 경보 시각은 유지합니다. 이 그래프의 시간은 입력 데이터 시간이며 PC 처리 시간이나 센서 전송 지연과는 구분합니다.

## 6. 모델 후보 비교

모델 크기는 Hidden 16, 32, 64와 다른 seed를 비교했습니다. 추가로 빠른 센서 5종만 사용하는 모델도 시험했습니다. 모델 선택에는 테스트 성능을 사용하지 않고 검증 데이터만 사용했습니다. 이번 합성 조건에서는 Hidden 16, 특징 15개의 후보를 선택했습니다. 15개 특징은 센서값 5개, 결측 표시 5개, 관측 후 경과 시간 5개입니다. 모델 파라미터는 2,065개입니다. 느린 센서의 원본 기록은 계속 보존하며, 실제 데이터에서도 느린 센서가 필요 없다는 결론은 내리지 않았습니다. 긴 온습도 추세를 분석하려면 별도의 장기 입력과 실제 정답 검증이 필요합니다.

## 7. 학습 곡선과 PR 곡선

최대 학습 횟수는 50회로 설정했고, 검증 손실에 따라 학습률 감소와 조기 종료를 적용했습니다. 선택 모델은 32회에서 종료됐고, 최종 저장에는 24회차의 가중치를 사용했습니다. 왼쪽 손실 곡선은 실제 저장된 학습 기록이고, 오른쪽은 별도 테스트의 PR 곡선입니다. 검증 손실이 후반에 증가하는 부분도 그대로 표시했습니다. PR 곡선은 임계값별 precision과 recall의 절충을 보여 줍니다. 면적이 높아도 실제 선택 임계값의 오경보와 미탐지가 없어지는 것은 아니므로 다음 혼동행렬을 함께 봅니다.

## 8. 테스트 분류 결과

별도 테스트 입력 1,620개에서 정상 1,437개와 위험 164개를 올바르게 분류했습니다. 정상 입력을 위험으로 예측한 FP는 18개, 위험 입력을 정상으로 예측한 FN은 1개입니다. Precision은 0.901, Recall은 0.994, F1은 0.945입니다. 같은 데이터의 Logistic은 FN 13개, FP 8개였습니다. LSTM은 이 시험에서 미탐지가 적은 대신 오경보 입력이 더 많았습니다. 어떤 절충이 적절한지는 실제 운용 요구와 데이터로 결정해야 합니다.

## 9. 오경보와 시간 평가

입력별 FP와 실제 경보 횟수는 다릅니다. 여러 양성 입력이 하나의 경보로 이어질 수 있기 때문입니다. 이번에는 정상 구간에서 경보가 새로 시작하면 오경보 에피소드로 계산하고, 정상 구간에 경보가 유지된 시간도 따로 셌습니다. 혼합 테스트에서 FP는 18개였지만, 정상 구간에서 시작한 새 경보는 0회였습니다. 위험 후 정상으로 돌아온 뒤 경보가 잠시 유지돼 정상 경보 시간은 7.5초였습니다. 유효한 정상 시간 대비 약 1.30퍼센트입니다. 합성 위험 구간 8개는 모두 경보와 겹쳤고 감지 지연 중앙값은 0.5초였습니다. 별도 2시간 정상 입력에서는 경보가 0회였지만 이 한 시험만으로 실제 오경보율을 보장할 수는 없습니다. 물리 규칙이 확인되면 초과와 미달 조건별로 같은 지표를 다시 분석할 수 있습니다.

## 10. 모델 변환과 임베디드 준비

학습 모델을 SavedModel과 float32, float16, INT8 형식으로 변환해 실제 PC 추론을 실행했습니다. float32는 17,360바이트, float16은 14,260바이트였습니다. 두 형식의 테스트 판정 변화는 0개였습니다. INT8은 반복 계산을 펼친 그래프 때문에 379,576바이트로 커졌고, 판정도 2개 달라져 FP가 18개에서 20개가 됐습니다. 따라서 INT8이 항상 작거나 좋은 것은 아닙니다. C++ 전처리와 링 버퍼는 기준 입력 140개로 Python 결과와 일치함을 확인했습니다. 전체 자동 테스트는 165개를 통과했습니다. 확인한 링, 입력, 작업 공간의 합은 12,282바이트지만 이것은 전체 MCU RAM이 아닙니다. 실제 보드의 연산자 지원, tensor arena, firmware와 처리 기한은 아직 검증하지 않았습니다.

## 11. 남은 확인과 개발

현재 PC에서는 수신, 전처리, 링 버퍼, 모델 추론, 알림 판단, 이벤트 저장, 재생과 평가가 연결됩니다. 이벤트 저장 실패나 입력 장애를 정상 판정으로 바꾸지 않고 사유를 기록합니다. 다음은 세 가지입니다. 먼저 회사와 센서 기준의 방향, 단위, 온도 기준과 허용 오경보 및 지연을 확정해야 합니다. 다음으로 실제 측정값과 독립적인 정답을 확보해 재학습하고 조건별 테스트를 늘려야 합니다. 마지막으로 실제 통신 규격에 맞춘 어댑터와 목표 MCU를 연결해 메모리, 연산자와 최악 처리 시간을 측정해야 합니다. 현재 예측 대상은 입력 종료 시점의 상태이며, 미래 낙뢰 예측을 검증한 모델은 아닙니다.
