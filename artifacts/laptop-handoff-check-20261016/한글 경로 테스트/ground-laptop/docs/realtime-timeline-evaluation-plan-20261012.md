# 실시간 타임라인·데이터 확대·오경보 평가 보완 계획

작성일: 2026-10-12

전체 작업은 [통합 개발·검증 계획](integrated-development-plan-20261012.md)을 기준으로 진행한다. 이 문서의 타임라인·데이터 확대·오경보 요구는 통합 계획에 포함했으며, 이 문서는 상세 분석 근거로 보존한다.

상태: 개발 및 발표자료 수정 계획. 아래 목표 수치와 신규 기능은 아직 실행 결과가 아니다.

## 1. 목표와 현재 상태

발표는 데이터 수신, 최근 구간 갱신, 입력 준비, 모델 추론, 경보 판단, 이벤트 기록의 시간 흐름을 중심으로 구성한다. 원본 센서의 측정 주기는 획득 설정과 부연 설명에 보존한다. 실제로 수신하지 않은 새 측정값을 만들어 실시간 입력처럼 취급하지 않는다.

현재 PC 합성 학습 실험은 입력 16개 시점·20개 특징, 총 882개 시퀀스(Train 441 / Validation 147 / Test 294)이다. LSTM의 평가 임계값은 0.5이며, Test 혼동행렬은 [[158, 46], [0, 90]]이다. 여기서 FP 46은 정상으로 지정한 합성 시퀀스를 위험으로 분류한 개수이다. 실제 낙뢰 46건이나 독립적인 경보 46회를 뜻하지 않는다.

별도 링 버퍼 데모는 3,600개 입력, 최대 66개 유지, READY 882개를 확인했다. 현재 모델 실시간 추론·상태 판단·자동 이벤트 기록은 연결하지 않았다. 학습 실험과 링 버퍼 데모를 하나의 실시간 추론 실험으로 합쳐 설명하지 않는다.

표준 프로파일은 64개 시점·측정값 나이를 포함하는 입력의 초기 후보이다. 기존 16×20 모델과 입력 계약이 다르므로 이 설정을 사용하면 데이터·정규화·모델을 함께 다시 만들고 링 버퍼 용량도 재산정한다.

## 2. 기준 정의를 먼저 확정

서로 다른 네 가지 기준을 분리해서 저장하고 설명한다.

| 구분 | 정의 | 사용 목적 |
|---|---|---|
| 센싱 범위 | 센서가 제공한 측정 범위 | 범위 이탈 검토와 입력 품질 판단 |
| 센서 판정 규칙 | 물리량·단위·비교 방향·기준값·지속 조건 | 센서 위험 조건의 충족 여부 표시 및 규칙 모델 |
| 정답 label | 평가하려는 정상·위험 상태와 해당 시간 구간 | TP / FP / TN / FN 판정 |
| AI 경보 규칙 | 모델 점수의 진입·해제 임계값과 지속 조건 | 점수를 실제 경보 상태로 변환 |

센싱 범위 이탈은 센서 오류 또는 실제 극단 신호일 수 있어 원본과 검토 사유를 보존한다. 센서 기준과의 불일치만으로 실제 낙뢰 오경보나 미탐지를 확정하지 않는다.

### 센서별로 확인할 내용

| 센서 | 제공 자료의 값 | 확정할 내용 |
|---|---|---|
| 대지전위 a/b | 2, V AC 맥락 | `>` 또는 `>=`, `<` 또는 `<=` 중 방향·경계 포함 여부, 전압 기준과 RMS/peak |
| 누설전류 | 1 mA = 0.001 A | 상한/하한 의미, 경계 포함 여부, 순간값 또는 지속값 |
| 제한소자 온도 a/b/c | 25℃ | 절대온도 / 초기값 대비 상승량 / 외기 대비 차이, 비교 방향, 지속 시간 |
| 상대습도 | 60% | 초과·미달 중 어느 조건을 사용하는지, 단독 경보 또는 보조 특징 |
| 외기온도 | 비교값 | 독립 임계값의 존재 여부, 온도 차이 계산에 사용하는지 |
| 입력전압 | 사용전압 비교 | 단위·정격전압·허용 편차, 저전압/과전압의 양방향 규칙 |
| 번개센서 | H=1 / L=0 | H가 뜻하는 장치 상태와 평가 정답으로 사용할 수 있는지 |

누설전류 1 mA와 온도 25℃는 표에 적힌 센싱 범위의 하한과도 같다. 모든 항목에 동일한 '기준값 이상이면 위험' 규칙을 적용하기 전에 이 관계를 확인한다. 미확정 항목은 자동 판정을 비활성화하고 확인 대기 상태를 표시한다.

규칙마다 측정량, 단위, 기준값, 연산자, 비교 기준, 경계 포함 여부, 지속 시간, 해제 조건, 센서 신선도 제한, 다중 센서 AND/OR 조합, 근거 문서와 버전을 기록한다. 비교 방식은 상한·하한·양방향 범위·온도 차이·변화율 중 확인된 항목만 활성화한다. 변화율과 온도 차이에는 별도로 확인한 기준값이 필요하다.

현재 `ThresholdBaseline`은 명시 규칙이 없고 센서 threshold가 있으면 `ge`를 자동으로 적용한다. 표준값을 운영 설정에 넣기 전에 이 기본 추정을 제거하고, 방향과 단위를 명시한 규칙만 허용하도록 수정한다.

정답은 회사가 확인한 상태 정의와 실측·실험 기록을 우선한다. AI 출력이나 검증하려는 동일한 센서 규칙으로 실제 낙뢰 정답을 만들어 성능을 주장하지 않는다. 규칙을 재현하는 과제가 목적이라면 결과를 '규칙 재현 성능'으로 명시한다. 미래 예측을 평가하려면 예측할 사건, 미래 시간 범위, 선행 경보 허용 구간을 별도로 정의한다. 현재 상태 분류 결과는 그대로 유지한다.

## 3. 실시간 타임라인 구성

| 타임라인 단계 | 동작 | 기록할 내용 |
|---|---|---|
| 관측·수신 | 센서 관측과 패킷 도착 | 관측 시각, 수신 시각, 출처·장치 |
| 검사·전처리 | 유효성 검사와 인과적 시간 정렬 | 무효 사유, 결측, 마지막 관측값의 나이 |
| 최근 구간 갱신 | 링 버퍼에 특징 추가 | 최신 구간, 사용량, 덮어쓰기 |
| 입력 준비 | 충분하고 유효한 연속 구간 확인 | WARMING_UP / READY / 입력 불가 사유 |
| 모델 추론 | 고정 feature 순서·scaler로 추론 | 모델 점수, 모델 버전, 처리 시간 |
| 상태 판단 | 진입·해제·지속 규칙 적용 | 정상 / 위험 알림 / 판정 불가, 판단 근거 |
| 이벤트 기록 | 경보 전후 구간 보존 | 시작·종료, 원본·특징·점수·규칙 버전 |

발표용 타임라인은 같은 시간축에 센서값과 확인된 기준선, 모델 점수와 AI 임계값, 정답 구간과 경보 구간을 배치한다. 결측·통신 장애·판정 불가 구간도 표시한다. 처리 결과를 확보하기 전에는 구조 설명 예시로 표시하고 실행 결과처럼 제시하지 않는다.

처음에는 1배속 CSV 재생으로 연속 입력을 연결하고 2배속·10배속·최대속도 재생으로 추가 검증한다. 이는 PC 재생 검증이며 실제 센서 연동과 MCU 실시간 검증은 별도로 수행한다.

센서 관측 주기, 정렬 간격, 모델 추론 간격, 처리 지연을 구분한다. 현재 데모의 정렬 간격은 100 ms, stride 4는 입력 준비 간격 약 400 ms에 해당한다. 표준 초기 설정의 stride 10은 약 1초에 해당한다. 목표 추론 간격과 허용 지연은 위험 판단 요구사항과 장치 예산에 맞춰 선택하고 측정한다. 시작 직후에는 입력 길이만큼의 유효한 구간을 기다리는 준비 시간이 있다.

느린 센서는 마지막 유효 관측값과 값의 나이를 사용한다. 미래값 보간은 사용하지 않는다. 짧은 입력으로 시간 단위의 온습도 추세를 학습했다고 설명하지 않는다. 그런 추세가 필요하면 더 긴 과거 특징을 별도로 설계한다.

실시간 상태는 알려진 정답 event_id로 초기화하지 않는다. 초기화 경계는 데이터 획득 시작·재시작 등 명시한 운용 정책을 따른다. 지연·역순·중복 패킷과 큐 적체를 처리할 정책도 기록하며, 버려진 입력을 집계한다.

PC 처리 시간은 단조 시계로 측정한다. 장치 관측 시각과 PC 수신 시각의 시계가 맞지 않으면 두 값을 단순히 빼서 전달 지연이라고 보고하지 않는다. 추론 지연과 수신부터 판단까지의 지연을 따로 기록하고, MCU에서 같은 항목을 다시 측정한다.

## 4. 데이터 확대 계획

첫 단계는 학습·평가용 합성 시나리오 60개와 별도 입력 오류 시나리오 10개를 마련한다. 각 구간을 60초·100 ms 기준으로 구성하면 원본은 약 42,000행이다. 아래 숫자는 초기 개발 목표이며 실제 낙뢰 성능을 입증하기 위한 충분한 표본 수를 의미하지 않는다.

| 시나리오 | 초기 목표 | 변화시킬 조건 |
|---|---:|---|
| 정상·정상 잡음 | 20개 | 기준선, 잡음 크기, 정상 변동, 센서별 상관관계 |
| 기준 주변 | 10개 | 기준 미달·정확히 동일·초과, 짧은 출렁임과 지속 이탈 |
| 단일 센서 변화 | 10개 | 상승·하락·급변·완만한 변화, 변화 시작 시각 |
| 복합 센서 변화 | 10개 | 동시·시간차 변화, AND/OR 규칙 비교 |
| 전환·회복·반복 경보 | 10개 | 정상에서 위험으로 전환, 회복, 반복 진입·해제 |
| 입력·통신 오류 | 별도 10개 | 결측, stale, 센서 고착, 중복·역순, 지연, 재연결 |

동일 파형을 복사하거나 같은 seed의 구간을 잘게 나누어 수를 늘리지 않는다. 생성 파라미터와 seed를 독립적으로 바꾸고, 새로 유입되지 않은 느린 센서 값을 원본 행마다 새 측정값으로 복제하지 않는다. 이 합성 데이터는 소프트웨어 시나리오이며 물리적 낙뢰 모사로 설명하지 않는다.

60개 학습·평가 구간은 초기 후보로 Train 36 / Validation 12 / Test 12로 그룹 분리한다. 정상과 위험을 두 평가 분할에 모두 포함하고 유사 파형·같은 획득 세션이 다른 분할에 섞이지 않도록 한다. 별도 오류 구간은 입력 품질·판정 불가 테스트에 사용하며 오류를 정상 label로 채우지 않는다.

시퀀스 개수는 입력 길이·stride·결측 제외에 따라 달라지므로 실제 빌드 후 집계한다. 보고서는 원본 행 수, 유효 관측 수, 독립 시나리오/획득 세션 수, 실제 위험 이벤트 수, 시퀀스 수와 정상 운전 시간을 분리해서 표시한다.

별도로 장시간 정상 연속 재생과 느린 센서 업데이트를 포함하는 시간 단위 테스트를 마련한다. 짧은 60초 구간만으로 시간당 오경보나 시간 단위 센서 추세를 충분히 검증했다고 결론 내리지 않는다.

실측 단계에서는 장치·날짜·환경별 정상 연속 기록과 확인된 위험 이벤트를 확보한다. 합성과 실측 출처를 구분하고 최종 실측 평가를 따로 보고한다. 자연 운용의 정상/위험 비율을 보존한 평가도 필요하다.

## 5. 오경보·미탐지 판정 및 분석

입력 시퀀스 수준에서, 확인한 정답을 기준으로 아래 정의를 사용한다. 미확정·무효 label과 판정 불가 입력은 정상으로 처리하지 않고 별도로 집계한다.

| 정답 | AI 위험 판정 | 의미 |
|---|---|---|
| 정상 | 없음 | TN: 정상 판정 |
| 정상 | 있음 | FP: 오경보 |
| 위험 | 없음 | FN: 미탐지 |
| 위험 | 있음 | TP: 위험 탐지 |

센서 위험 조건의 충족 여부를 세 번째 분석 축으로 추가한다.

| 센서 규칙 상태 | 정답 | AI 경보 | 분석 |
|---|---|---|---|
| 위험 조건 미충족 | 정상 | 없음 | 정상 판정 |
| 위험 조건 미충족 | 정상 | 있음 | AI 오경보 원인 분석 |
| 위험 조건 충족 | 정상 | 없음 | AI 정상 판정, 센서 규칙과 label의 의미 검토 |
| 위험 조건 충족 | 정상 | 있음 | 정답 기준 AI 오경보, 센서값과 label 검토 |
| 위험 조건 미충족 | 위험 | 없음 | 미탐지, 시간 패턴·복합 조건 검토 |
| 위험 조건 미충족 | 위험 | 있음 | 위험 탐지, 정답과 감지 시점 검토 |
| 위험 조건 충족 | 위험 | 없음 | 미탐지, 규칙 감지와 AI 결과 비교 |
| 위험 조건 충족 | 위험 | 있음 | 위험 탐지 |

여기서 '위험 조건 충족'은 확인된 경보 규칙의 비교식이 참인 상태이다. 예를 들어 초과 경보 규칙 `x > 기준값`에서는 초과일 때, 미달 경보 규칙 `x < 기준값`에서는 미달일 때 조건을 충족한다. 기준값과 같을 때는 확인한 경계 연산자에 따라 판정한다. 비교 방향이 미확정이거나 입력이 불가하면 이 표의 확정 상태로 넣지 않는다. 정답이 없을 때는 AI와 규칙의 일치·불일치를 보고하고 실제 FP/FN은 계산하지 않는다.

오경보 사례마다 원본 센서값·단위·기준 대비 차이, 모델 점수, 최신 입력 구간, 값의 나이, 통신 상태, 경보 지속 시간, 정답 근거를 남긴다. 기준에 가까운 정상 잡음, 짧은 이탈, 복합 조건, 회복 구간, 입력 장애, 새 환경으로 나눠 원인을 분석한다.

### 시간 흐름에서의 경보 집계

모델의 매 입력 판정과 실제 상태 경보를 따로 집계한다. 경보 진입 임계값, 해제 임계값, 연속 확인 조건, 재진입·병합 조건을 validation에서 선택하고 고정한다. 연속 양성 입력을 모두 독립 경보로 세지 않는다. 경보가 길게 유지된 경우 정상 시간 중 경보가 켜진 시간도 함께 보고한다. 지속 조건으로 짧은 오경보를 줄이는 실험에서는 짧은 위험을 놓치는지와 감지 지연도 함께 비교한다.

이벤트 평가는 정답 위험 시작·종료 시각과 허용 탐지 구간을 먼저 정의한다. 경보 시작을 어떤 이벤트와 연결할지, 반복 경보와 여러 이벤트의 겹침을 어떻게 처리할지도 시험 전에 고정한다. 현재 상태 감지는 미래 예측의 선행 허용 구간을 자동으로 사용하지 않는다.

| 지표 | 집계 기준 |
|---|---|
| 입력 오경보율 | FP / (FP + TN) |
| 입력 미탐지율 | FN / (FN + TP) |
| 독립 경보 횟수 | 상태 진입·해제 규칙으로 묶은 경보 에피소드 |
| 정상 시간당 오경보 | 정상 유효 운전 구간의 오경보 에피소드 수 / 해당 운전 시간 |
| 정상 시간 중 경보 활성 비율 | 정상 구간의 경보 유지 시간 / 정상 유효 운전 시간 |
| 이벤트 탐지·미탐지 | 사전에 고정한 정답 이벤트·경보 매칭 규칙 |
| 감지 지연 | 확인된 위험 시작부터 해당 탐지까지의 시간 |
| 판정 가능 비율 | 전체 운전 시간과 입력 중 판단 가능한 비율, 중단 구간 사유 |

기존 FP 46과 22.55%는 합성 입력 시퀀스 수준의 값으로 보존한다. 정상 시간당 오경보·경보 횟수·감지 지연은 아직 계산하지 않았으므로 재생 및 상태 판단 연결 후 새로 측정한다. 정상 정답 또는 독립 이벤트 수가 없으면 해당 지표는 계산 불가로 표시한다. 겹치는 시퀀스를 독립 표본으로 삼아 성능의 불확실성을 과소평가하지 않는다.

임계값·모델·경보 지속 조건은 validation에서 선택하고 새 Test는 최종 평가에만 사용한다. 기존 Test의 FP를 이미 살펴보았으므로 그 데이터를 수정 방향 검토에 사용한 경우 새로운 최종 holdout을 확보한다. 요구 재현율·허용 오경보·허용 지연은 회사의 운용 요구에 맞춰 확정한다. 확정 전에는 후보별 절충 관계를 보여주고 최적 운용값이라고 단정하지 않는다.

## 6. 실행 순서와 완료 조건

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| A | 목표 상태·센서 규칙·정답 정책 정의 | 비교 방향과 경계·label 근거를 명시하고 미확정 항목을 구분 |
| B | 합성 시나리오 확대·실측 수집 양식 준비 | 출처·생성 설정·그룹 분할·해시를 저장하고 목표 구간과 유효 개수를 보고 |
| C | 재학습·검증 | Logistic·LSTM·확정 규칙 모델을 같은 분할로 비교, train-only 정규화, 새 Test 보호 |
| D | PC 연속 재생과 추론·판단·기록 연결 | 알려진 정답 경계 없이 연속 동작, 무효 입력 처리, 경보 전후 기록, 단계별 시각 보존 |
| E | 오경보 원인·경보 에피소드 평가 | 입력/이벤트/시간 지표를 구분하고 센서 위험 조건의 충족·미충족별 사례 제시 |
| F | PPT와 대본 갱신 | 실제 새 결과를 반영하고 계획·PC 재생·실측·MCU 결과를 구분 |
| G | 임베디드 적용 | 목표 MCU 예산 확인, 변환 전후 출력 비교, 실제 메모리·실행시간 측정 |

확정 기준을 기다리는 동안에는 입력 연속성·타임라인 기록·오류 시나리오와 임의 단위 소프트웨어 fixture를 진행할 수 있다. 기준이 확정되기 전에는 해당 물리 규칙을 활성화하거나 물리적 정답으로 설명하지 않는다.

모델 보완은 작은 LSTM과 Logistic을 유지하면서 입력 길이·특징·모델 크기를 제한된 후보로 비교한다. 학습 예산은 train/validation에서 검토하고 best checkpoint·학습률 감소·조기 종료를 유지한다. 미래 정보나 label·event_id를 센서 특징으로 넣지 않는다. 실제 판정 출력과 경보 상태의 보류율까지 비교한다.

기존 검사·전처리·scaler·RingBuffer·SequenceBuilder를 재사용한다. 수정 범위는 센서 규칙 설정과 `ThresholdBaseline`, 합성 데이터 설정·생성, `src/realtime`의 추론/상태/기록/재생 연결, `src/evaluation`의 시간·이벤트 지표와 해당 테스트이다. 새로운 서버나 메시지 브로커는 이 단계에 필요하지 않다. 기존 데이터·모델·PPT는 보존하고 새 실험 버전으로 저장한다.

## 7. 추가 테스트

기준 바로 아래·동일·바로 위의 값은 센서 해상도와 확인한 경계 연산자를 기준으로 시험한다. 방향별 상한·하한·양방향 판정을 확인하고, 온도 차이 규칙은 기준 온도의 결측·stale도 시험한다.

연속 수신에서는 초기 입력 부족, 링 버퍼 여러 차례 순환, 큰 timestamp 공백, 중복·역순 입력, 센서 동시 고장, 통신 지연·재연결, 긴 정상 구간, 반복 경보, 이벤트 기록 중 다음 입력 수신을 시험한다. 경보 해제 조건을 입력 장애가 대신 충족시키지 않도록 정책을 확인한다.

평가에서는 window FP와 경보 횟수가 다르게 집계되는 사례, 하나의 긴 오경보, 무효 label, 판정 불가 구간, 정상 분모가 없는 경우, 반복 이벤트 매칭, 배치/연속 전처리와 추론의 일치를 확인한다. 실제 MCU의 메모리·최악 처리시간·누락 입력은 장치에서 별도로 확인한다.

## 8. PPT 수정 구성

기존 11장 흐름을 바탕으로 다음 내용을 반영한다. 글은 핵심 정의와 실제 수치 중심으로 줄이고 상세 규칙·부연 설명은 발표자 노트에 넣는다.

| 슬라이드 | 수정 방향 |
|---|---|
| 1 | 실시간 데이터 흐름·학습 평가의 범위 |
| 2 | 센서 기준값과 초과/미달·온도 기준의 확정 상태. 측정 주기는 부연 설명으로 이동 |
| 3 | 확대 데이터의 실제 원본·시나리오·분할·시퀀스 수. 생성 전에는 목표로 표시 |
| 4 | 시간에 따라 이동하는 최신 입력 구간과 링 버퍼 동작 |
| 5 | 수신·입력 준비·추론·경보·기록 타임라인. 단계별 실제 지연과 판정 불가 표시 |
| 6 | 재학습 모델과 확정 입력 계약·학습 제어 |
| 7 | 새 학습 곡선·PR 곡선과 validation 임계값 선택 |
| 8 | 정답 기준 FP/FN 정의, 입력 오경보율과 경보 횟수의 구분 |
| 9 | 센서 위험 조건의 충족/미충족별 사례 타임라인, 미달·동일·초과 분석 |
| 10 | Logistic·LSTM·확정 규칙 비교와 검증 범위·판정 가능 비율 |
| 11 | 남은 실측 검증·모델 보완·테스트·MCU 적용 |

오경보 사례 그림은 센서값·기준선, AI 점수·임계값, 정답·경보 상태를 같은 시간축에 보여준다. 확인한 정상 사례와 실제 위험 사례를 각각 넣고, 입력 오류 사례는 판정 불가 상태로 구분한다. 새 실험을 진행하기 전에는 기존 평가 수치를 임의로 바꾸지 않는다.

## 9. 확인한 프로젝트 근거와 공식 참고

- `configs/sensor_standard_reference.yaml`: 숫자 기준값은 기록되어 있으나 비교 연산자와 온도 비교 기준은 미확정.
- `configs/preprocessing_standard.yaml`, `configs/realtime_demo.yaml`: 표준/데모 입력과 stride 차이.

- `src/dataset/labeling.py`: 명시 label mapping과 미확정 label 처리.
- `src/evaluation/metrics.py`: validation 임계값 선택, 입력 단위 혼동행렬, 회고적 event group 요약.
- `src/realtime/buffer_demo.py`: 정답 fixture 경계 초기화와 모델 미연결 상태.
- `artifacts/models/demo-20261005-233045/report.json`: 기존 합성 Test 수치와 범위.
- `artifacts/reports/ring-buffer-demo.json`: 링 버퍼 별도 실행 결과.
- `output/presentations/그라운드_4회차_LSTM_링버퍼_추가_방경식.pptx`: 현재 발표자료의 구성과 수치.

정답과 예측의 혼동행렬 정의는 [scikit-learn confusion_matrix 공식 문서](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.confusion_matrix.html)를 확인했다. 모델 출력과 판정 임계값의 분리 및 독립 검증 데이터에서 임계값을 조정하는 원칙은 [분류 임계값 조정 공식 문서](https://scikit-learn.org/stable/modules/classification_threshold.html)를 따른다. train-only 전처리와 Test를 모델 선택에 사용하지 않는 원칙은 [데이터 누출 방지 공식 문서](https://scikit-learn.org/stable/common_pitfalls.html)를 따른다. 센서별 위험 방향과 실제 label 의미는 이 ML 문서가 정해주지 않으며 제공한 장치 사양과 확인된 운용 정의를 사용한다.
