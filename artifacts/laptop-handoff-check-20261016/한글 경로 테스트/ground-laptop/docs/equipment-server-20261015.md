# 장비 열화 점검·서지 활동 서버 실험

2026-10-15 사용자 요구를 반영한 별도 서버 실험이다. 기존 `integrated-20261012`의 모델·기준 기록·발표자료는 보존한다. 새 모델은 장비 열화 점검과 서지 활동을 따로 학습하고, 10개 센서를 모두 사용한다. MCU 메모리·Flash·모델 크기는 모델 선택 조건으로 사용하지 않는다.

## 회사 자료와 이번 구현의 구분

[그라운드 공식 모니터링 설명](https://eca3g.com/home/sub.php?menukey=487)은 장비 동작, 누설전류, 전위차, 서지 카운터를 모니터링하며, 카운터가 낙뢰 서지뿐 아니라 일정 수준 이상의 과전압 서지도 센다고 설명한다. 따라서 누적 횟수 증가를 독립적인 실제 낙뢰 확인으로 단정하지 않고 `surge` 활동으로 분리했다. 공식 설명은 이번 프로젝트의 2 mA·45℃·70% 수치를 해당 제품의 인증 기준으로 확정해 주는 자료가 아니다.

[공식 카탈로그](https://eca3g.com/home/images/sub/ground_catalogue.pdf)의 9쪽에는 220 V와 380 V 등의 제품 사양, 26쪽에는 ON-365와 고객 서버를 활용하는 모니터링 구성이 있다. 이를 확인했으며 모든 장비의 정격을 220 V로 일괄 가정하지 않는다. 합성 데이터의 전압 기준 220 V는 재현 실험용 설정이고 실제 설치 장비의 정격 확인을 대체하지 않는다.

## 반영한 기준과 데이터 의미

| 항목 | 새 서버 실험의 처리 |
|---|---|
| 대지전위 A/B | 각각 2 V AC 이상이면 점검 조건 충족 |
| 누설전류 | 2 mA = **0.002 A 이상**이면 점검 조건 충족 |
| 제한소자 A/B/C | 각각 절대온도 **45℃ 이상**. 독립 입력과 외기온도 대비 온도차도 각각 계산 |
| 상대습도 | **70% 이상**이면 점검 조건 충족 |
| 외기온도 | **25℃를 환경 기준값**으로 사용. 25℃ 이상을 자동으로 열화·낙뢰 정답으로 만들지 않음 |
| 입력전압 | 측정값을 유지하고, 기준전압을 지정한 경우 차이와 상대 편차 계산. 기준 미지정이면 비교값은 미확인 |
| 낙뢰센서 | 0/1 대신 **비음수 정수 누적 서지 횟수**. 증가량의 `log1p`, 최근 10초 발생률, 리셋·증가량 확인 여부로 변환 |
| 낙뢰 없는 온도 상승 | 개별 소자 발열과 외기온도 상승을 서지 활동과 분리 |
| 낙뢰 후 전압 반응 | 카운터 증가 전후 A/B 관측값, 변화량, 0 V까지의 거리를 기록. 실제 에너지 변환을 소프트웨어가 수행하거나 성공을 보증하지 않음 |
| 서버 시험 | LSTM 32/64/128 후보 비교. 크기 페널티·MCU 탑재 가능성 필터 없음 |

비교 방식은 사용자 위임에 따라 `>=`와 절대온도를 기본으로 선택했다. 사용자 제공 수치와 엔지니어링 기본 해석을 설정의 `criteria_provenance`에 구분해 기록했다. 이 기준의 충족은 유지보수 점검 신호이며, 확정 고장·수명·낙뢰 정답과 같지 않다. 경계값과 단위 변환은 별도 시험한다.

입력전압 비교 기준은 `pipeline.equipment_features.input_voltage_reference`로 명시한다. 기본 센서 설정은 미확인인 `null`이고, 이번 합성 실험의 recipe만 220 V를 사용한다. 원본의 `input_voltage_reference` 열은 실험 출처 기록이며 매 행 모델의 기준을 바꾸는 입력이 아니다. 실제 장비 정격이 달라지면 새 설정으로 전처리·학습·평가하며, 저장된 bundle의 manifest를 직접 고치지 않는다.

카운터 초기값은 과거 발생 횟수이므로 새 사건으로 계산하지 않는다. 감소는 리셋으로 분리하고 증가량은 미확인으로 표시한다. 통신 공백이나 잘못된 계수값 이후에도 새 기준점을 확보한다. 음수·소수·bool·비유한 수·정확한 정수로 표현하기 어려운 값은 유효한 카운터로 받지 않는다. 오래 누적된 총횟수를 모델 특징으로 직접 넣지 않아 가동 기간을 현재 서지 활동으로 오인하는 경로를 줄였다. 원본 기록에는 누적 총횟수를 보존한다.

## 입력 구성과 학습

모든 센서를 활성화하고 총 **39개 특징**을 사용한다. 10개 센서 값 중 누적 카운터는 증가량 함수로 대체하고, 센서별 missing/age 20개와 카운터·환경·전압 비교 특징 9개를 추가한다. 모든 변환은 현재와 과거의 관측만 사용한다. 정규화와 결측치 대체값은 학습 구간에서만 구한다.

빠른 센서의 정렬 격자는 0.1초, 입력 창은 64개 시점, 추론 stride는 10이다. 제한소자 온도의 60초, 습도·외기온도의 3,600초 관측 주기를 유지한다. 관측이 없는 행에는 새 측정값을 만들어 채우지 않는다. 이 6.4초 창은 느린 센서의 현재 상태를 맥락으로 쓰며, 시간 단위의 열화 추세나 실제 잔여수명을 학습했다고 주장하지 않는다.

독립적인 이진 모델 두 개를 사용한다.

- `degradation`: 합성 장비 점검 상태. 실제 고장 확정 모델이 아니다.
- `surge`: 최근 합성 서지 활동. 실제 낙뢰 확정 모델이 아니다.

정상·점검·서지·점검과 서지 동시 상태를 조합해 출력한다. 한 작업이라도 판정 불가이면 전체 상태는 `UNAVAILABLE`이고 기존 경보 상태는 별도로 유지한다. 실제 정답이 없는 입력의 각 작업 정답은 `UNLABELED`로 처리한다. 입력에 정답 열이 있더라도 특징에는 넣지 않는다.

각 작업에 LSTM 32/64/128을 학습하고 validation에서 재현율 목표 충족 여부, F1, 재현율, 오경보 수 순으로 선택한다. Test 점수와 모델 크기는 후보 순위에 사용하지 않는다. 최대 50 epoch, 검증 손실 기반 조기 종료·학습률 감소·최적 checkpoint 저장을 적용한다. 경보 임계값과 연속 확인·해제 설정도 validation에서 선택한다. 학습 방법은 [TensorFlow 공식 학습 가이드](https://www.tensorflow.org/guide/keras/training_with_built_in_methods)와 [EarlyStopping API](https://www.tensorflow.org/api_docs/python/tf/keras/callbacks/EarlyStopping)를 확인했다.

## 합성 데이터와 평가 범위

17개 시나리오 종류, 85개 획득 세션, **153,000행**을 생성했다. 세션 단위로 Train 51개/91,800행, Validation 17개/30,600행, Test 17개/30,600행을 분리한다. 작업별 입력 창은 Train 8,874개, Validation 2,958개, Test 2,958개다. 두 작업은 같은 입력을 사용하고 정답만 다르므로 데이터 수를 두 배의 독립 측정으로 계산하지 않는다.

시나리오는 정상, 높은 외기온도, 높은 누적 총횟수, 카운터 리셋, 소자 A/B/C 개별 발열, 서지 없는 발열, 누설전류, 대지전위 A/B, 습도, 복합 변화, 서지만 발생, 점검과 서지 동시, 전압 반응 미발생, 입력전압 편차를 포함한다. 합성 원인과 정답을 먼저 정한 뒤 관측을 생성하며, 설정한 기준의 비교 결과를 그대로 정답으로 복사하지 않는다. 그래도 합성 과정과 정답은 같은 시험 설계에서 나오므로 독립 실측 검증을 대신할 수 없다.

‘서지 후 0 V 방향으로 감소’는 설정 가능한 가상 응답이며 기본 시정수 0.5초는 제조사 측정값이 아니다. 전압 감소·유지·고온·카운터 리셋을 분석 경로에서 처리하는지 시험하는 용도다. 기록의 `protection_success`와 `lightning_confirmed`는 미확인으로 남긴다. 입력 전압 전체를 0 V로 강제 설정하거나 실제 하드웨어를 작동시키지 않는다.

각 작업별 오경보/미탐지, 정상 시간당 경보 시작 횟수, 정상 경보 시간, 감지 지연, 가용 범위를 보고한다. 점검 기준×정답×AI 예측 비교도 장비 점검 작업에서 별도 집계한다. 서지 활동 작업에 장비 점검 기준을 낙뢰 정답처럼 적용하지 않는다. 전압·온도 기준만으로 완벽한 물리 고장을 확정하지 않는다.

## 실행

완료된 서버 모델로 두 작업을 함께 재생한다. 명령은 프로젝트 폴더의 PowerShell에서 실행한다.

```powershell
$out = Join-Path '.\artifacts' ('server-replay-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff'))
.\.venv-ml\Scripts\python.exe -m src.realtime.equipment_server `
  --run .\artifacts\server-equipment-20261015 `
  --input .\data\raw\equipment-server\server-equipment-20261015\heldout.synthetic.csv `
  --output $out
Get-Content (Join-Path $out 'summary.json') -Raw -Encoding UTF8
```

노트북에서도 프로젝트의 소스·설정·아래 새 모델과 입력을 복사한 뒤 같은 상대경로 명령을 사용한다. 새 모델 목록은 run 내부의 상대경로로 연결되므로 데스크탑의 `run.json` 절대경로를 실행에 사용하지 않는다. 가상환경 설치는 [노트북 안내](windows-laptop-setup.md)를 따른다. 이전 7,200행·15특징 모델은 이전 실험이며 새 열화 기준 검증에 사용하지 않는다.

새 학습·비교·평가 전체 실행:

```powershell
$newRun = Join-Path '.\artifacts' ('server-equipment-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff'))
.\.venv-ml\Scripts\python.exe -m scripts.run_equipment_server `
  --config .\configs\equipment_server.yaml --output $newRun
```

이 명령은 CPU 학습을 포함한다. 처음부터 새로운 결과 경로를 사용하며 기존 결과를 덮어쓰지 않는다. 이미 해석된 센서 관측을 `EquipmentServer.feed()`에 넣는 분석 경계와 파일 재생 CLI를 제공한다. 이후 추가한 [발표 시연 화면](presentation-demo.md)은 로컬 합성 입력 재생용 HTTP 서비스다. 실제 운영 서버 API·ON-365 통신 decoder·통신 규격·실측 정답은 추가 검증 대상이다.

## 검증 결과

전체 테스트 **319개**, 새 회귀 시험 **34개**가 통과했다. 기존 Keras/NumPy DeprecationWarning 45개는 남는다.

| 작업 | 선택 LSTM | 완료 epoch / 최적 epoch | Test F1 | Test 재현율 | Test FP / FN |
|---|---|---|---|---|---|
| degradation | lstm32 | 50 / 47 | 0.9993 | 0.9987 | 0 / 2 |
| surge | lstm32 | 49 / 49 | 1.0000 | 1.0000 | 0 / 0 |

표는 작업별 Test 입력 창 2,958개에 대한 분류 지표이며, 실제 낙뢰 사건 수나 장비 고장 확률이 아니다.

- 각 작업의 실제 Keras 모델로 Test 30,600행을 재생했다. 10개 센서와 39개 특징을 유지했다.
- 작업별 2,958개 Test 창에서 저장된 학습 입력과 현재 실시간 경로의 입력 텐서가 정확히 일치했고, 저장된 Test 점수와의 최대 차이는 다음과 같다: {"degradation": 5.960464477539063e-08, "surge": 1.862645149230957e-08}
- 두 작업을 함께 출력하는 CLI도 9,000행에서 정상 종료했고, 두 이벤트 recorder의 저장 완료를 확인했다.
- 기준 7개의 미달·동일·초과 21개 경계 상황을 실모델 경로에 통과시켜 점검 조건을 확인했다. 이 상황의 물리 고장 정답은 UNLABELED로 유지했다.
- 두 모델을 다른 폴더로 복사해 상대경로 연결과 동일 입력 출력을 확인했다. 실제 노트북의 새 설치 환경을 시험한 것은 아니다.
- 실제 TensorFlow 오류를 주입해 전체 판정 불가, 기존 서지 경보 유지, 이후 복구를 확인했다.
- 관측 카운터 증가를 직접 사용하는 기준선과 AI 점수를 따로 기록했다. 카운터 증가 자체를 실제 낙뢰의 독립 정답으로 주장하지 않는다.
- 이전 모델·선택 설정·발표자료 등 98개 원본 파일의 SHA256이 모두 유지됐다.
- 증거는 `artifacts/server-upgrade-20261015/tests-final.xml`, `tests-equipment.xml`, `runtime-verification.json`, `verification.json`, `training.log`에 있다.

합성 데이터는 모델 구조와 소프트웨어 동작을 검증하는 용도다. 실측 정답, 실제 서버 환경, 장비별 전압 기준과 전압 응답은 별도 확인해야 한다.
