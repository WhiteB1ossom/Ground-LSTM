수행내용
1. 프로젝트 개요
본 프로젝트는 기존 낙뢰 방어장치에서 취득되는 센서 데이터를 활용하여 LSTM 기반 시계열 분석을 수행하고, 향후 장비에서 활용할 수 있는 판단용 출력값을 도출하는 것을 목적으로 한다.
기업에서 검토 중인 입력 데이터는 전압, 전류, 온도, 습도, 낙뢰 검지 주파수, 낙뢰 검지 거리, 대지 전위차 등이며, 각 데이터의 기준값 또는 상·하한 범위를 바탕으로 데이터셋을 구성하는 방향이다. 또한 실제 장비 적용을 고려하여 모델의 정확도뿐만 아니라 제한된 하드웨어 환경에서 활용할 수 있는 경량화 가능성도 함께 검토한다. 이번 프로젝트의 범위는 낙뢰 방어장치 전체 제어시스템을 직접 구현하는 것이 아니라, 입력 데이터 구성·정제 → LSTM 분석 → 활용 가능한 출력값 도출까지를 중심으로 한다.
2. LSTM 적용 개요
LSTM(Long Short-Term Memory)은 시간의 흐름에 따라 변화하는 데이터를 분석하는 시계열 딥러닝 모델이다. 일반적인 기준치 방식은 현재 센서값이 특정 기준을 초과하였는지를 중심으로 판단한다. 반면 LSTM은 현재값뿐만 아니라 과거부터 현재까지 센서값이 어떠한 방향으로 변화하였는지를 함께 분석할 수 있다. 예를 들어 동일한 현재값이라도 값이 지속적으로 증가하고 있는 경우에는 위험 기준으로 접근하고 있는 상태일 수 있으며, 반대로 값이 감소하고 있는 경우에는 위험상태에서 안정상태로 복귀하고 있는 과정일 수 있다. 따라서 본 프로젝트에서는 LSTM을 기존 기준치를 대체하는 용도로 보기보다, 기존 기준값과 함께 센서 데이터의 변화 추세를 분석하여 위험상태로 접근하는 과정 또는 안정화되는 과정을 판단하기 위한 보조 분석수단으로 활용하는 방향을 검토한다.
3. 데이터 처리 시나리오 설정
센서 데이터는 장비가 동작하는 동안 지속적으로 발생하므로 모든 데이터를 계속 저장할 경우 저장용량과 관리대상이 불필요하게 증가할 수 있다. 이에 따라 평상시에는 최근 일정 시간의 데이터만 임시로 유지하고, 낙뢰 위험 또는 이상 징후가 확인되는 경우에만 해당 시점 전후의 데이터를 별도로 저장하는 시나리오를 검토하였다. 이를 위하여 Ring Buffer 방식을 적용하는 방안을 고려하였다.
Ring Buffer는 최근 일정 시간의 데이터만 유지하고 새로운 데이터가 입력되면 가장 오래된 데이터를 순차적으로 덮어쓰는 방식이다. 이를 통해 LSTM 분석에 필요한 최근 데이터는 유지하면서 정상상태에서 발생하는 모든 원시데이터를 장기간 저장하지 않을 수 있다.
기본적인 처리 흐름은 다음과 같다.
센서 데이터 입력
      ↓
Ring Buffer
최근 일정시간 데이터 유지
      ↓
LSTM 시계열 분석
      ↓
위험도 또는 상태 판단
      ↓
정상 → 기존 데이터 순차적 덮어쓰기
위험 → 관련 데이터 별도 저장
4. 낙뢰 전·후 데이터 저장 시나리오
낙뢰 방어시스템에서는 낙뢰 발생 이전의 데이터가 가장 중요하다. 낙뢰가 발생하기 전에 어떠한 센서 변화가 나타나는지를 분석하여 위험상태로 접근하는 패턴을 파악하는 것이 사전 대응의 핵심이기 때문이다. 다만 낙뢰가 감지된 이후의 데이터도 짧은 구간을 추가로 저장하는 것이 필요하다고 판단하였다.
예를 들어 다음과 같은 구조이다.
[낙뢰 감지 전 데이터]
↓
[감지 시점]
↓
[낙뢰 감지 후 데이터]
감지 전 데이터는 낙뢰 발생 이전에 나타나는 변화패턴을 분석하는 예측 및 사전 판단용 데이터로 활용한다. 감지 후 데이터는 LSTM이 위험상태로 판단한 이후 실제 센서값이 어떻게 변화하였는지를 확인하는 결과 검증용 데이터로 활용한다.
즉 낙뢰 후 데이터를 저장하는 목적은 낙뢰를 방지하기 위한 직접적인 판단에 있는 것이 아니라, LSTM의 판단이 실제 상황과 일치하였는지를 확인하고 향후 모델을 개선하기 위한 근거 데이터를 확보하는 데 있다. 예를 들어 개념적으로 감지 전 30초와 감지 후 10초를 저장할 수 있으나, 구체적인 시간은 향후 센서 샘플링 주기와 실제 데이터 특성을 확인한 후 결정한다. 이를 통하여 평상시의 대량 데이터는 최소화하면서 낙뢰와 관련된 가치 있는 데이터만 선택적으로 축적할 수 있다.
5. 전체 시스템 구조
현재 검토 중인 전체 구조는 다음과 같다.
전압 / 전류 / 온도 / 습도
낙뢰 검지 주파수 / 낙뢰 검지 거리 / 대지 전위차
↓
 데이터 수집
↓
Ring Buffer
최근 데이터 임시 유지
↓
LSTM
시계열 변화패턴 분석
↓
위험도 또는 상태 출력
↓
기업 기준정보와 함께 판단
↓
위험 징후 발생 시 전·후 저장
↓
결과 검증 및 데이터 축적
LSTM의 최종 출력은 위험도, 정상·주의·위험 등의 상태값, 또는 일정 시간 이후의 상태 예측 등으로 구성할 수 있으며, 구체적인 출력형태는 기업에서 실제 장비에 어떠한 정보를 필요로 하는지 확인한 후 결정한다.
6. 프로젝트 관리 및 향후 진행방향
프로젝트 수행과정에서 발생하는 데이터 전처리 코드, LSTM 모델, 실험결과 및 문서는 GitHub를 활용하여 버전별로 관리하는 방안을 검토한다. GitHub에는 코드와 모델 설정, 실험결과 및 기술문서를 관리하고, 기업의 실제 센서 원본 데이터와 대용량 데이터는 별도의 저장공간에서 관리한다. 이를 통해 프로젝트 진행과정과 모델 변경사항을 추적하고 회차별 결과를 체계적으로 관리한다. 향후에는 기업에서 제공하는 센서별 기준값, 측정단위, 샘플링 주기, 실제 데이터 형태를 확인하고 LSTM 입력 Window의 크기와 최종 출력형태를 구체화한다. 이후 실제 데이터 기반으로 모델을 구성하고, 입력 데이터 수와 모델 구조를 조정하여 정확도와 경량화 수준을 비교할 예정이다.
본 프로젝트의 전체 방향은 기존 기준정보를 유지하면서 LSTM을 통해 센서의 시간적 변화패턴을 추가로 분석하고, Ring Buffer를 활용하여 필요한 최근 데이터만 관리하며, 위험 발생 전·후 데이터를 선택적으로 축적하여 향후 판단 신뢰성과 모델 성능을 개선하는 구조로 정리한다.
이 버전이면 LSTM 자체 설명은 짧게 유지하면서도 왜 Ring Buffer를 사용하는지, 왜 낙뢰 전·후 데이터를 저장하는지, 전체 시나리오가 어떻게 이어지는지가 중심에 드러난다. 실제 수행일지에는 이 정도 밀도가 가장 적절해 보인다.
