# 실제 모델 구동 시연

발표용 로컬 화면에서 **센서 입력 → 시간 정렬 → 링 버퍼 → 학습된 LSTM 2개 → 점검 경보**를 보여준다. 모델을 다시 학습하지 않고 `artifacts/server-equipment-20261015`의 장비 점검·서지 활동 모델을 불러온다. 점수는 입력이 들어올 때 실제로 계산한다. 입력은 보관된 **합성 Test 데이터**이며 실제 장비를 연결한 측정 시연은 아니다.

## 실행

프로젝트 폴더의 **`run-demo.cmd`를 더블클릭**한다. 브라우저가 열리고, 모델 로딩이 끝나면 `모델 준비 완료`가 표시된다. 실행 창은 시연이 끝날 때까지 열어 둔다.

PowerShell에서 직접 실행할 수도 있다.

```powershell
.\.venv-ml\Scripts\python.exe -m src.realtime.demo --open
```

주소는 **http://127.0.0.1:8765** 이다. 이미 실행 중이면 이 주소만 열면 된다. 프로그램을 중복 실행하면 포트 사용 중 오류가 생길 수 있다. 다른 프로그램이 이 포트를 쓰면 다음처럼 바꾼다.

```powershell
.\.venv-ml\Scripts\python.exe -m src.realtime.demo --port 8766 --open
```

종료는 실행 창에서 `Ctrl+C`를 누른다. 노트북에서 `.venv-ml`이 없으면 먼저 [Windows 노트북 설정](windows-laptop-setup.md)을 따른다. 모델과 데이터가 모두 복사되어 있으면 시연 중 인터넷은 필요 없다. GPU 없이 CPU로 실행할 수 있다.

## 발표 시연 순서

처음에는 `발열 + 서지`를 선택하고 **처음부터 재생**을 누른다. 배속은 10배를 권장한다. 준비 구간은 버퍼가 차는 것을 보여주도록 1배속이며, 이후 선택한 배속으로 바뀐다. 화면의 시간은 원본 센서 시간이다. 배속을 바꾸어도 측정 timestamp·센서 주기·모델의 입력 창은 바뀌지 않는다. CPU가 처리 속도를 따라가지 못하면 실제 재생은 더 느려질 수 있다.

1. **입력 준비:** 처음에는 점수가 비어 있고 `판정 준비 / 불가`가 나온다. 64개 시점이 모이면 첫 추론을 수행한다. 이후 10개 시점마다 새 점수를 계산한다.
2. **링 버퍼:** 저장량이 114개까지 늘어난다. 이후에는 저장 크기를 유지하면서 `덮어쓰기` 횟수가 늘어난다. 화면의 파란 칸은 최신 추론 창 64개를 뜻하며 물리 메모리 주소를 보여주는 것은 아니다. 두 작업은 동일한 입력 계약을 쓰며 화면은 장비 점검 작업의 버퍼를 표시한다.
3. **독립적인 두 판단:** 센서 시간 60초에 관측 온도가 바뀌고, 65초에 합성 서지 카운터가 증가한다. 온도 기준 비교와 장비 점검 모델 점수를 보고, 이어서 서지 모델 점수와 경보를 본다. 경보는 저장된 임계값과 연속 확인 정책을 따른다.
4. **입력 분리 확인:** `서지 없는 발열`을 처음부터 재생해 장비 점검 경보와 서지 경보가 구분되는지 보여준다.
5. **오해 방지 확인:** `카운터 리셋`의 90초에서 누적값이 감소해도 새 발생으로 세지 않는 것을 동작 기록으로 보여준다. `정상`과 `서지만 발생`도 선택할 수 있다.

각 상황은 처음부터 끝까지 1,800행, 센서 시간 약 180초다. 10배속에서는 준비 구간을 포함해 대략 25초이며 PC 성능에 따라 달라진다. 시나리오를 선택한 뒤 재생을 누르면 별도의 획득 세션으로 버퍼와 경보를 시작한다. 세션 안의 정답 label이 바뀌는 것으로 버퍼를 초기화하지 않는다. 일시정지는 파일 재생을 멈추는 기능이며 통신 단절 시험을 뜻하지 않는다.

발표 중 짧게 설명한다면:

> 지금 보이는 입력은 합성 Test 데이터를 시간 순서대로 재생한 것입니다. 학습된 두 LSTM이 입력을 받아 실제로 점수를 계산합니다. 링 버퍼에 최근 입력을 유지하다가 64개 시점이 모이면 추론하고, 이후 일정 입력 간격마다 갱신합니다. 온도가 올라가는 상황과 서지 카운터가 증가하는 상황을 각각 판단하기 때문에, 서지가 없어도 장비 점검 신호를 낼 수 있습니다. 실제 장비 연동과 현장 성능 검증은 다음 단계입니다.

## 화면과 기록 해석

- 점수는 0~1 범위의 모델 출력이다. 실제 고장 확률이나 낙뢰 확률로 해석하지 않는다. `추론 ms`는 마지막 개별 모델 호출 시간이며 전체 입력 지연·통신 지연을 뜻하지 않는다.
- 두 모델의 진입·해제 임계값과 연속 확인 횟수는 해당 모델의 `replay-selected.yaml`에서 읽는다. 센서 기준값과 모델 점수 임계값은 서로 다른 설정이다.
- 센서 표의 주황색은 기준 비교 결과다. 누설전류는 입력 A를 화면에서 mA로 변환한다. 온도·습도처럼 느린 센서는 마지막 관측값과 관측 후 경과 시간을 함께 표시한다.
- 외기온도 25℃는 참조값이다. 입력전압 220V는 이 합성 실험의 참조값이다. 누적 서지 센서는 낙뢰 및 과전압 서지 활동을 포함할 수 있으므로 실제 낙뢰로 확정하지 않는다.
- 점수 계산이 실패하면 오류와 판정 불가 상태를 표시한다. 기존 경보가 유지될 때는 `경보 유지 · 판정 불가`로 표시한다. 화면과 서버의 연결이 끊기면 마지막 값이라는 안내를 표시한다.
- 실행별 기록은 `artifacts/presentation-demo/<실행시각-임의번호>/`의 `timeline*.jsonl`, `summary.json`에 저장한다. 재생 중단·완료와 오류가 요약에 구분된다. 이 시연 기록은 기존 모델과 입력을 덮어쓰지 않는다. 이벤트 전후 파일 저장을 포함한 기존 전체 CLI는 [서버 실행 안내](equipment-server-20261015.md)를 따른다.

화면은 이 PC의 `127.0.0.1`에만 열리는 발표용 서비스다. ON-365 통신 decoder나 실제 운영 서버 API를 대체하지 않는다. 브라우저 창이 작으면 전체화면과 확대/축소를 조절해 보여줄 수 있다.

## 검증 기록

발표 시연 테스트 11개를 포함한 전체 **330개 테스트가 통과**했다. 기존 Keras/NumPy 경고 45개는 남는다. 실제 두 LSTM과 HTTP 제어 경로로 정상·서지만 발생·서지 없는 발열·발열과 서지·카운터 리셋을 각각 1,800행씩 재생했다. 각 상황에서 작업별 실제 추론 174회, 처리 오류 0회, 저장 오류 0회였고, 일시정지 중 입력 진행이 멈춘 뒤 재개되는 것도 확인했다. 이는 선택한 합성 소프트웨어 사례의 동작 결과다.

증거는 `artifacts/demo-check-20261016-002419-382/tests.xml`, `live-verification.json`, 같은 폴더의 검증 스크립트에 있다. 브라우저 연결 도구가 비어 있어 실제 브라우저 렌더링·화면 클릭은 자동 검증하지 못했다. 브라우저 JavaScript 문법과 HTTP 페이지·제어 API는 확인했다.
